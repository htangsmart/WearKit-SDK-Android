# Scan, filter, connect, and disconnect

## Purpose and supported scope

This guide covers discovering a wearable with BLE scan, then connecting it to the process-wide `WKWearKit` (the data channel may be BLE or Classic Bluetooth SPP):

- Scan with `wearKit.scanner` for a single `WKDeviceType`.
- Filter results the SDK already applies for that family (manufacturer company ID, optional empty-name drop).
- Connect with `wearKit.connector.connect(...)`, observe `WKConnectorState`, then `close()` or `clear(...)`.
- Optional auto-reconnect, bonding, and auth mode (`WKAuthMode`).

Call feature abilities only after `WKConnectorState.CONNECTED`.

Documented public version: **3.0.2.7**.

## Prerequisites

- Complete [Setup: dependencies and initialization](001.setup.md). You already hold an application-scoped `WKWearKit` and `RxBleClient`.
- Register a `WKWearKit.Builder` for **every** family you will scan. `wearKit.scanner.scan(type, …)` routes to that family’s kit. A Gradle dependency without a builder cannot serve that `WKDeviceType`.
- Runtime Bluetooth permissions and an enabled Bluetooth adapter (see [Permissions](#permissions-lifecycle-threading-errors-cleanup)).
- A stable `userId` string for `connect`. The sample uses the logged-in user id. Do not pass an empty id unless your product contract allows it.
- Physical device advertising for the family you scan. Adapter presence does not guarantee a given watch will appear.

## Call sequence

1. Confirm Bluetooth runtime permissions and `wearKit.isAdapterEnabled()` (or your own adapter observer). On API 30 and below, also keep location services on if you want the same behavior as the Android BLE stack typically requires.
2. Subscribe to `wearKit.scanner.scan(type, durationSeconds, checkLocationService, acceptEmptyName)`.
3. Collect `WKScanResult` (`device`, `name`, `rssi`, optional `projectNum` / `subProjectNum`). Stop the scan when the user picks a device (`dispose`).
4. Subscribe to `wearKit.connector.observeConnectorState()` **before** `connect` if the UI must show connecting. Use `.startWithItem(wearKit.connector.getConnectorState())` so the current value is not missed. Optionally subscribe to `observeConnectorError()`.
5. Call the recommended `connect` overload (auth + user body metrics). `connect` is **not** an Rx type; it starts work internally.
6. Treat only `WKConnectorState.CONNECTED` as ready for abilities. `PRE_CONNECTED` means the underlying link is up (BLE GATT or SPP) but the SDK is still running prepare operations.
7. To leave the device without auto-retry of that address, call `close()`. To unbind (clear device auth, optional Android bond, then close), subscribe to `clear(removeBond)`.
8. Dispose scan and observe subscriptions with the owning lifecycle.

Do not call `disconnect()` / `reconnect()` for normal UX. Both are `@Discouraged`; KDoc says most apps should use `close()` or `clear()`.

## Kotlin example

Based on `DeviceScanActivity` / `ScannerHelper` (scan) and `DeviceActivity` / `SanagDeviceFeature` (connect). Duration is **seconds**, matching `WKScanner` and `InternalBaseScanner` (`take(..., TimeUnit.SECONDS)`). The WearKit sample currently passes `120 * 1000` into `durationSeconds`; that is **not** milliseconds. Use a value such as `120` unless you intentionally want a very long scan.

Use `WKAuthMode` (`typealias` of `AuthMode`). The sample `DeviceActivity` imports `FwAuthMode`, which is the same enum type; third-party code should import `WKAuthMode`.

```kotlin
package com.example.wear

import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity
import com.polidea.rxandroidble3.exceptions.BleScanException
import com.topstep.wearkit.apis.WKWearKit
import com.topstep.wearkit.apis.model.core.WKAuthMode
import com.topstep.wearkit.apis.model.core.WKConnectorState
import com.topstep.wearkit.apis.model.core.WKDeviceType
import com.topstep.wearkit.apis.model.core.WKScanResult
import io.reactivex.rxjava3.android.schedulers.AndroidSchedulers
import io.reactivex.rxjava3.disposables.CompositeDisposable
import io.reactivex.rxjava3.disposables.Disposable

class ScanConnectActivity : AppCompatActivity() {

    private val wearKit: WKWearKit get() = (application as App).wearKit
    private val disposables = CompositeDisposable()
    private var scanDisposable: Disposable? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        disposables.add(
            wearKit.connector.observeConnectorState()
                .startWithItem(wearKit.connector.getConnectorState())
                .observeOn(AndroidSchedulers.mainThread())
                .subscribe { state ->
                    when (state) {
                        WKConnectorState.DISCONNECTED -> { /* idle or closed */ }
                        WKConnectorState.PRE_CONNECTING,
                        WKConnectorState.CONNECTING,
                        WKConnectorState.PRE_CONNECTED -> { /* connecting / preparing */ }
                        WKConnectorState.CONNECTED -> { /* abilities are allowed */ }
                    }
                }
        )
        disposables.add(
            wearKit.connector.observeConnectorError()
                .observeOn(AndroidSchedulers.mainThread())
                .subscribe { error ->
                    // error.throwable, error.retryNumber, error.retryContinue, error.bleScanException
                }
        )
    }

    fun startScan(type: WKDeviceType) {
        if (scanDisposable?.isDisposed == false) return
        if (!wearKit.isAdapterEnabled()) return

        scanDisposable = wearKit.scanner.scan(
            type = type,
            durationSeconds = 120,
            checkLocationService = true,
            acceptEmptyName = false,
        )
            .observeOn(AndroidSchedulers.mainThread())
            .subscribe(
                { result: WKScanResult -> onDeviceFound(result) },
                { throwable -> onScanError(throwable) },
                { /* duration elapsed */ },
            )
        disposables.add(scanDisposable!!)
    }

    fun stopScan() {
        scanDisposable?.dispose()
        scanDisposable = null
    }

    fun connect(type: WKDeviceType, address: String, userId: String) {
        stopScan()
        wearKit.connector.connect(
            type = type,
            address = address,
            authMode = WKAuthMode.AUTO,
            authCode = null,
            userId = userId,
            sex = true,
            age = 30,
            height = 175f,
            weight = 70f,
        )
    }

    fun disconnectAndForget() {
        wearKit.connector.close()
    }

    fun unbind(removeAndroidBond: Boolean) {
        disposables.add(
            wearKit.connector.clear(removeAndroidBond)
                .observeOn(AndroidSchedulers.mainThread())
                .subscribe({ /* unbound */ }, { /* log */ })
        )
    }

    private fun onDeviceFound(result: WKScanResult) {
        // result.device.address, result.name, result.rssi
    }

    private fun onScanError(throwable: Throwable) {
        val reason = (throwable as? BleScanException)?.reason
            ?: BleScanException.UNKNOWN_ERROR_CODE
        when (reason) {
            BleScanException.BLUETOOTH_DISABLED,
            BleScanException.BLUETOOTH_NOT_AVAILABLE,
            BleScanException.LOCATION_PERMISSION_MISSING,
            BleScanException.LOCATION_SERVICES_DISABLED -> { /* already gated in UI */ }
            BleScanException.SCAN_FAILED_ALREADY_STARTED,
            BleScanException.UNDOCUMENTED_SCAN_THROTTLE -> { /* retry after a short delay */ }
            else -> { /* unknown; after repeats, ask the user to toggle Bluetooth */ }
        }
    }

    override fun onDestroy() {
        disposables.dispose()
        super.onDestroy()
    }
}
```

Production apps usually keep `connect` / `close` at application scope so navigation does not drop the watch. The sample `DeviceActivity` calls `close()` when the activity is finishing; that is demo teardown, not a required SDK contract.

## Scan behavior

`WKScanner.scan`:

| Parameter | Meaning |
|---|---|
| `type` | `WKDeviceType.FIT_CLOUD`, `FLY_WEAR`, `SHEN_JU`, `PROTO_TB`, or `AB_MATE`. Wrong type for the active family kit throws `IllegalArgumentException`. |
| `durationSeconds` | Observable completes after this many **seconds** (`Observable.take(..., TimeUnit.SECONDS)` in `sdk-base`). |
| `checkLocationService` | Default `true`. If true, RxAndroidBle / ShenJu may fail with `BleScanException.LOCATION_SERVICES_DISABLED` when location is off. The sample sets this to `false` and shows its own location banner on API 30 and below. |
| `acceptEmptyName` | Default `false`. Drop advertisements whose name is null or empty. Name is read only when connect runtime permission is granted. |

`WKScanner` KDoc: family filter; foreground `SCAN_MODE_LOW_LATENCY` vs background `SCAN_MODE_LOW_POWER` (from `ProcessLifecycleObserver.isForeground()`); one retry on `BleScanException.UNDOCUMENTED_SCAN_THROTTLE` (delay capped at 30 s).

Each emission is a `WKScanResult`. Equality includes name, rssi, and project fields; `hashCode` is only `device.hashCode()`. Deduplicate in the UI by address if you need a stable list. `projectNum` / `subProjectNum` are filled when manufacturer payload is long enough (FitCloud / ProtoTb / AbMate path through `BaseScanner`). FlyWear mapping in the adapter does not copy those fields.

Do not scan all families in one `WKScanner.scan` call. Pass one `WKDeviceType`. The sample `MainActivity` starts a separate `DeviceScanActivity` per family. `ScannerHelper` with `type == null` bypasses WearKit and uses raw `RxBleClient.scanBleDevices`; that is a demo “unfiltered BLE” path, not the public WearKit filter.

`WKScanner.qrcode(content)` is documented on the interface as **not yet implemented**. Adapter behavior today: ProtoTb parses a URL (`ma`, `na`, `ty`, optional `co`; `ty` must be `w30`) into `WKQrCodeResult`; FitCloud, FlyWear, and ShenJu adapters return `null`. Do not treat QR bind as a portable public contract until the interface comment is updated. The sample scan screen has a QR menu and Manifest activity name; there is no `DeviceQrCodeActivity` source in the current sample tree.

## Connect, auth, reconnect, bond

Recommended overload (KDoc: “for most apps”):

`connect(type, address, authMode, authCode, userId, sex, age, height, weight)`

There is a second overload without body metrics. Prefer the first unless you will call `setUserInfo` / `syncUserInfo` immediately after `CONNECTED`.

`WKAuthMode`:

| Value | KDoc |
|---|---|
| `BIND` | First bind of this user to the device. |
| `LOGIN` | Reconnect / already bound. |
| `AUTO` | SDK chooses; sample uses this. |

`authCode`: pass only when you obtained it from the watch QR code. Sample uses `null`.

`connect` on the core manager switches the active family proxy (`changeProxyKit`) then forwards. After connect, `getDevice()` is the held `BluetoothDevice` until `close()`. `getDeviceType()` / `getDeviceToken()` are `@RestrictTo(LIBRARY_GROUP)` and must not be used by host apps as a connected check.

`WKConnectorState`:

| State | Meaning |
|---|---|
| `DISCONNECTED` | Idle, after `close()`, adapter off, auto-reconnect disabled, or interrupt. Use `getDisconnectedReason()` when you need a reason enum. |
| `PRE_CONNECTING` | Waiting before the next attempt. |
| `CONNECTING` | Actively connecting (may scan the target first). |
| `PRE_CONNECTED` | Link up (BLE GATT or SPP); prepare ops running; **do not** run feature abilities. |
| `CONNECTED` | Prepared. `isBindOrLogin()` is true for BIND, false for LOGIN. |

Default auto-reconnect in the core connector wrapper is `WKAutoReconnectMode.BALANCED` and `setAutoReconnectInterval` **5** seconds. Modes:

| Mode | Behavior (from `AutoReconnectMode` KDoc) |
|---|---|
| `NEVER` | No auto reconnect. |
| `LOW_POWER` | Trigger on app foreground, Bluetooth on, or screen on. No timer. |
| `BALANCED` | Those triggers plus a timer (foreground ~5 s; background at least 5 s, backoff). |
| `LOW_LATENCY` | Those triggers plus a 5 s timer in foreground and background. |

`close()` disconnects and **clears** the held device (no reconnect of that address until you `connect` again). `disconnect()` keeps the device and may reconnect later. `reconnect()` retries if a device is held.

`clear(removeBond)`: clear auth on the device (some firmware factory-reset), optionally `removeBond` if `getDeviceCanBond()` is bonded, then `close()`. Subscribe to the `Completable`.

Bonding: `setAutoCreateBond(true)` is the manager default. `createBond()` / `removeBond()` return `Single<Optional<BluetoothDevice>>`. Dual-mode or optional-bond hardware is family-specific; do not assume classic pairing is required.

After connect, `setUserInfo(...)` always overwrites device user metrics. `syncUserInfo(WKUserInfo)` may keep the device copy when its timestamp is newer; unsupported devices behave like a force write. Sample UI: `UserInfoActivity`.

## Permissions, lifecycle, threading, errors, cleanup

### Permissions

Same Bluetooth permissions table as [001.setup.md](001.setup.md#permissions): API 23–30 location (`ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`); API 31+ `BLUETOOTH_SCAN` and `BLUETOOTH_CONNECT`. Use `RxBleClient.getRecommendedScanRuntimePermissions` / the sample `PermissionHelper`.

Declare those permissions in the **host** Manifest. The WearKit sample declares `BLUETOOTH` / `BLUETOOTH_ADMIN` (maxSdk 30) plus `BLUETOOTH_SCAN` and `BLUETOOTH_CONNECT`.

On API 31+, scan does not need location for the RxAndroidBle-recommended permission set. Below 31, location permission and often location services are required. Sample `DeviceScanActivity` hides the location-service banner on API 31+.

Request Bluetooth permissions (and, if your product uses EPO / device GPS, location) **before** `connect`. Sample `DeviceActivity` requests Bluetooth permissions then location, then `connect`.

### Lifecycle and threading

- Keep `WKWearKit` in `Application`. Connector state is process-wide.
- Dispose `scan()` when the scan UI stops (`ScannerHelper` disposes in `onStop`).
- Observe scan and connector streams on `AndroidSchedulers.mainThread()` for UI.
- Drive `ProcessLifecycleManager.setForeground` as in setup; it selects scan power mode and reconnect triggers.
- `connect` / `close` may be called from the main thread; they are synchronous API entry points that start internal work.

### Errors and cleanup

- Scan errors: `BleScanException` reasons handled in `ScannerHelper.analysisScanError`.
- Connection errors: `observeConnectorError()` emits `WKConnectorError` (`throwable`, `retryNumber`, `retryContinue`, optional `bleScanException`). The main sample does not subscribe; Sanag demo notes mention it.
- When `DISCONNECTED`, `getDisconnectedReason()` is the public enum (`INIT_STATE`, `ACTIVE_CLOSE`, `BT_DISABLED`, `DISCONNECT_TEMPORARY`, `DISCONNECT_DFU`, `AUTH_LOGIN_FAILED`, `AUTH_BIND_FAILED`, `AUTO_RECONNECT_DISABLED`, `ERROR_UNKNOWN`). `getDisconnectedCause()` is library-group only.
- Dispose observers; do not `release()` the kit per Activity.
- Keep the RxJavaPlugins ignore set from setup so undeliverable BLE errors do not crash the process.

## Device-family, firmware, version, and feature limitations

- Scan filters by family manufacturer IDs inside each adapter (FitCloud, ProtoTb, AbMate, FlyWear, ShenJu). Unknown watches are omitted. You cannot pass a custom company-ID filter through `WKScanner`.
- `SHEN_JU` uses `SJUniWatch.startDiscovery` / `stopDiscovery`, not the shared `BaseScanner` path.
- Firmware that is not advertising, is in DFU, or is bound to another phone may not appear or may fail `AUTH_*`.
- `WKWearKit.observeAdapterEnabled(replay)` exists for adapter on/off; the sample scan UI uses its own `flowBluetoothAdapterState` instead.
- Do not enable vendor test flags such as `PbSDK.COMPANY_ID_ALL` in production (also noted in setup).

## Verification

1. Init succeeds ([001.setup.md](001.setup.md#verification)).
2. Grant Bluetooth permissions; enable Bluetooth (and location services on API &lt; 31 if `checkLocationService` is true).
3. Start scan for the family of a nearby, advertising watch. Within `durationSeconds`, a `WKScanResult` with a plausible name and RSSI appears. Timber scanner logs include address / name / companyId on the `BaseScanner` path.
4. `connect` with `WKAuthMode.AUTO`. UI moves `CONNECTING` / `PRE_CONNECTED` then `CONNECTED`. `getDevice()?.address` matches the scanned MAC.
5. Toggle Bluetooth off: state becomes `DISCONNECTED` (reason may be `BT_DISABLED`). Turn Bluetooth on: with default `BALANCED`, reconnect should start without a second `connect` **if** you did not `close()`.
6. `close()`: device is forgotten; no timer reconnect until you `connect` again.
7. Feature buttons in the sample toast “Device not connected” unless state is `CONNECTED`.

Expected result: one held device on `wearKit.connector`, state `CONNECTED`, ready for ability guides.
