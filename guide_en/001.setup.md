# Setup: dependencies and initialization

## Purpose and supported scope

This guide covers the **minimum host-app setup** required before you scan or talk to a device:

- Add the WearKit Maven repository (or equivalent local AARs) and declare dependencies.
- Plant Timber, create a shared `RxBleClient`, register process foreground/background, call `buildWKWearKit`, then install the SDK RxJava ignored-exception set.
- Keep the resulting `WKWearKit` for the lifetime of the application process.

WearKit is a unified wearable SDK (`com.topstep.wearkit`). **Scan is always BLE**; after a connection is established the data channel may be BLE or Classic Bluetooth SPP, depending on the device family (and firmware). Host apps still use one entry point. After initialization you obtain `WKWearKit` and later use `scanner`, `connector`, and ability APIs. Device families are selected by registering the matching `WKWearKit.Builder` implementations:

| Device family (`WKDeviceType`) | Adapter artifact | Builder |
|---|---|---|
| `FIT_CLOUD` | `sdk-fitcloud-adapter` | `WKFitCloudKit.Builder` |
| `FLY_WEAR` | `sdk-flywear-adapter` | `WKFlyWearKit.Builder` |
| `SHEN_JU` | `sdk-shenju-adapter` | `WKShenJuKit.Builder` |
| `PROTO_TB` | `sdk-prototb-adapter` | `WKProtoTbKit.Builder` |
| `AB_MATE` | `sdk-abmate-adapter` | `WKAbMateKit.Builder` |

Registering an adapter does **not** mean every device of that family supports every ability. Feature support is per firmware and ability `Compat` APIs (documented in later feature guides).

Documented public version in `WearKit-SDK-Android/README.md` and `CHANGED.md`: **3.0.2.7**. Keep every WearKit artifact on the **same** version. Do not mix Maven modules with a mismatched local AAR set.

## Prerequisites

- Android application module, Kotlin, Java 8 language level.
- Host-app `minSdk`: **26** is recommended. If you do not integrate AiKit speech AI (`com.topstep.aikit`), you may lower it to **24**.
- Bluetooth hardware and Bluetooth permissions (see [Permissions](#permissions)).
- A Timber `Tree` planted **before** SDK objects are created. WearKit logs through Timber; it does not plant a tree for you.
- RxJava 3. Do not replace `RxJavaPlugins.setErrorHandler` with an empty swallow-all handler. Merge the SDK ignore set with any types your own app must ignore.

Add feature-only host libraries (FFmpeg, AliAgent, `camera-core`, …) only when that feature is used — see comments in the dependency blocks below.

### Common duplicate-class conflicts

`sdk-fitcloud-adapter` (via `sdk-fitcloud`) pulls in the required artifacts `ext-realtek-bbpro` and `ext-realtek-file` (`wearKit.musicAbility` / `wearKit.eBookAbility` / `wearKit.albumAbility`). Exclude them on the adapter only when the host already ships the same Realtek classes and Gradle reports **duplicate class**:

```kotlin
implementation("com.topstep.wearkit:sdk-fitcloud-adapter:$wearkitVersion") {
    exclude(group = "com.topstep.wearkit", module = "ext-realtek-bbpro")
    exclude(group = "com.topstep.wearkit", module = "ext-realtek-file")
}
```

With local AARs there is no POM exclude: add `ext-realtek-bbpro-*.aar` and `ext-realtek-file-*.aar` by default. Omit them only when the host already provides equivalent classes and a duplicate-class conflict occurs.

## Initialization sequence

Call this from the **main application process** `Application.onCreate` (the sample creates `RxBleClient` and `WKWearKit` only in the main process).

1. Plant Timber.
2. Create a single `RxBleClient` with **application** context: `RxBleClient.create(application)`.
3. Implement `ProcessLifecycleManager` (or `ProcessLifecycleObserver`) and register it so you can call `setForeground(true/false)` on process foreground/background.
4. Build a non-empty `List<WKWearKit.Builder>`. Each builder takes `(Application, ProcessLifecycleObserver, RxBleClient)`.
5. `val wearKit = buildWKWearKit(builders)` from `com.topstep.wearkit.core`. An empty list throws `IllegalArgumentException`. One builder returns that kit directly; several builders are wrapped in an internal manager that switches the active proxy after connection.
6. Merge `wearKit.rxJavaPluginsIgnoreExceptions()` into `RxJavaPlugins.setErrorHandler`.
7. Hold `wearKit` (and usually `rxBleClient`) in application scope. Do not create a new kit per Activity.

Optional builder flags exist on some families (`setAutoSetTime`, `setAutoSetLanguage`, FitCloud AliAgent, FlyWear/ShenJu `setLogPath`). The sample uses constructor defaults.

`WKWearKit.release()` exists and releases Bluetooth helper state and per-family kits. Call it only when you need to tear down the kit; host apps usually do not. The sample keeps the kit for process lifetime and does not call `release()`.

Vendor test flags (`PbSDK.COMPANY_ID_ALL`, connection-method switches) and `locationMapAbility.setLocation(...)` live in the sample `MyApplication` **after** `wearKitInit`. They are not part of minimum setup. Copy `wearKitInit` only; skip those extras unless you need EPO / device GPS or are running the sample’s vendor tests.

## Kotlin example

Based on `WearKit-SDK-Android/sample/app/src/main/java/com/topstep/wearkit/sample/WearKitInit.kt` and `MyApplication.kt`. Trim adapters you do not ship. Plant Timber yourself (the sample plants it inside `AppLogger` and comments the Timber block out).

```kotlin
package com.example.wear

import android.app.Activity
import android.app.Application
import android.os.Bundle
import android.util.Log
import com.polidea.rxandroidble3.RxBleClient
import com.topstep.wearkit.apis.WKWearKit
import com.topstep.wearkit.base.ProcessLifecycleManager
import com.topstep.wearkit.core.buildWKWearKit
import com.topstep.wearkit.fitcloud.WKFitCloudKit
import com.topstep.wearkit.flywear.WKFlyWearKit
import com.topstep.wearkit.prototb.WKProtoTbKit
import com.topstep.wearkit.shenju.WKShenJuKit
import io.reactivex.rxjava3.exceptions.CompositeException
import io.reactivex.rxjava3.exceptions.UndeliverableException
import io.reactivex.rxjava3.functions.Consumer
import io.reactivex.rxjava3.plugins.RxJavaPlugins
import timber.log.Timber

class App : Application() {

    lateinit var rxBleClient: RxBleClient
        private set
    lateinit var wearKit: WKWearKit
        private set

    override fun onCreate() {
        super.onCreate()
        if (BuildConfig.DEBUG) {
            Timber.plant(Timber.DebugTree())
        } else {
            Timber.plant(object : Timber.DebugTree() {
                override fun isLoggable(tag: String?, priority: Int): Boolean {
                    return priority > Log.DEBUG
                }
            })
        }
        rxBleClient = RxBleClient.create(this)
        wearKit = createWearKit()
    }

    private fun createWearKit(): WKWearKit {
        val processLifecycleObserver = AppProcessLifecycleManager().also {
            registerActivityLifecycleCallbacks(it)
        }
        val builders = ArrayList<WKWearKit.Builder>()
        builders.add(WKFitCloudKit.Builder(this, processLifecycleObserver, rxBleClient))
        builders.add(WKFlyWearKit.Builder(this, processLifecycleObserver, rxBleClient))
        builders.add(WKShenJuKit.Builder(this, processLifecycleObserver, rxBleClient))
        builders.add(WKProtoTbKit.Builder(this, processLifecycleObserver, rxBleClient))
        // builders.add(WKAbMateKit.Builder(this, processLifecycleObserver, rxBleClient))

        val wearKit = buildWKWearKit(builders)

        val ignoreExceptions = HashSet<Class<out Throwable>>()
        ignoreExceptions.addAll(wearKit.rxJavaPluginsIgnoreExceptions())
        RxJavaPlugins.setErrorHandler(RxJavaPluginsErrorHandler(ignoreExceptions))

        return wearKit
    }
}

private class AppProcessLifecycleManager : ProcessLifecycleManager(), Application.ActivityLifecycleCallbacks {
    private var startCount = 0

    override fun onActivityCreated(activity: Activity, savedInstanceState: Bundle?) = Unit

    override fun onActivityStarted(activity: Activity) {
        startCount++
    }

    override fun onActivityResumed(activity: Activity) {
        if (startCount == 1) {
            setForeground(true)
        }
    }

    override fun onActivityPaused(activity: Activity) = Unit

    override fun onActivityStopped(activity: Activity) {
        startCount--
        if (startCount == 0) {
            setForeground(false)
        }
    }

    override fun onActivitySaveInstanceState(activity: Activity, outState: Bundle) = Unit

    override fun onActivityDestroyed(activity: Activity) = Unit
}

private class RxJavaPluginsErrorHandler(
    private val ignores: Set<Class<out Throwable>>,
) : Consumer<Throwable> {

    override fun accept(t: Throwable) {
        if (handle(t)) return
        throw RuntimeException(t)
    }

    private fun handle(throwable: Throwable): Boolean {
        val cause = if (throwable is UndeliverableException) {
            throwable.cause
        } else {
            throwable
        } ?: return true

        if (cause is CompositeException) {
            var nullCount = 0
            for (e in cause.exceptions) {
                if (e == null) {
                    nullCount++
                } else if (isIgnore(e)) {
                    return true
                }
            }
            if (nullCount == cause.exceptions.size) {
                return true
            }
        } else if (isIgnore(cause)) {
            return true
        }
        return false
    }

    private fun isIgnore(throwable: Throwable): Boolean {
        val clazz = throwable::class.java
        for (ignore in ignores) {
            if (ignore.isAssignableFrom(clazz)) {
                return true
            }
        }
        return false
    }
}
```

`rxJavaPluginsIgnoreExceptions()` is the union of per-family sets. FitCloud, for example, includes `BleException`, `FcException`, `TimeoutException`, and `InterruptedException`. Unknown undeliverable errors must still fail; the sample rethrows `RuntimeException(t)`.

## Permissions, lifecycle, threading, errors, cleanup

### Permissions

Declare and request Bluetooth runtime permissions before scan/connect. The sample `PermissionHelper` follows `RxBleClient.getRecommendedScanRuntimePermissions`:

| API level | Bluetooth runtime permissions used by the sample |
|---|---|
| 23 until 31 | `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` |
| 31+ | `BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT` |

Also declare matching `<uses-permission>` entries in the host Manifest. The WearKit sample declares `BLUETOOTH` / `BLUETOOTH_ADMIN` (maxSdk 30) plus `BLUETOOTH_SCAN` and `BLUETOOTH_CONNECT`.

Location in the WearKit sample Manifest is also used for EPO / continuous location, which is separate from the Bluetooth permissions required for scanning on Android 12+. Camera, contacts, SMS, storage, and Wi-Fi permissions are feature-specific.

### Lifecycle and threading

- Create `RxBleClient` and `WKWearKit` on the application object, not in a short-lived Activity.
- Drive `ProcessLifecycleManager.setForeground` from activity start/stop (sample: foreground when the first activity resumes, background when the last activity stops).
- SDK APIs are RxJava 3. Observe on the thread required by UI or I/O in later guides; initialization itself is synchronous in `Application.onCreate`.

### Errors and cleanup

- `buildWKWearKit` requires at least one builder.
- Install `RxJavaPlugins.setErrorHandler` after the kit exists so `rxJavaPluginsIgnoreExceptions()` is available.
- Dispose feature/scan/connect observers with the owning lifecycle (see scan/connect). Do not dispose the application-scoped kit on every Activity `onDestroy`.
- When minify is enabled, SDK modules ship `consumer-rules.pro` (shared rules live mainly in `sdk-base`). If the host uses AGP older than 8.2, sealed classes inside AARs may require **R8 8.2+** (the SDK repo pins `com.android.tools:r8:8.2.47` for that reason). Current SDK AGP is 8.6.0.

## Device-family, firmware, version, and feature limitations

- Add an adapter **and** register its `Builder`. A Gradle dependency without a builder will not serve that family.
- Firmware and ability support are not implied by adapter presence.
- Internal engineering builds may use `3.0.2.7-SNAPSHOT`; third-party apps should use the version published in README (`3.0.2.7`) unless you were given snapshots on purpose.

## Verification

1. Sync Gradle: `sdk-core` and chosen adapters resolve at `3.0.2.7` (Maven) or the matching `*-v3.0.2.7.aar` files (local).
2. Launch the app process. No crash in `Application.onCreate`.
3. Confirm `wearKit` is initialized and `wearKit.isAdapterEnabled()` reflects Bluetooth adapter state when you toggle Bluetooth (optional sanity check; full scan is the next guide).
4. With Timber planted, SDK log tags appear (FitCloud uses a `Fc#` prefix in adapter code; the manager uses `WK#`).
5. Trigger a known undeliverable BLE error path only after scan/connect is wired; the process must not crash solely because those ignored types were delivered to `RxJavaPlugins`.

Expected result: one process-wide `WKWearKit` ready for `scanner` / `connector`. You have not yet bound a watch.
