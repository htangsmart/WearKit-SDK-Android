# 准备工作：依赖与初始化

## 目的与适用范围

本指南覆盖扫描设备或与设备通信之前，宿主 App 必须完成的**最小化接入配置**：

- 添加 WearKit Maven 仓库（或等效的本地 AAR）并声明依赖。
- 初始化 Timber、创建共享的 `RxBleClient`、注册进程前后台状态、调用 `buildWKWearKit`，然后安装 SDK 的 RxJava 可忽略异常集合。
- 将得到的 `WKWearKit` 在应用进程生命周期内持有。

WearKit 是面向可穿戴设备的统一 SDK（`com.topstep.wearkit`）。**扫描一律走 BLE**；连接建立后的数据通道可能是 BLE，也可能是经典蓝牙 SPP，取决于设备家族（及固件），宿主仍用同一套入口。初始化完成后得到 `WKWearKit`，后续通过 `scanner`、`connector` 和各 ability API 使用。设备家族通过注册对应的 `WKWearKit.Builder` 实现来选择：

| 设备家族（`WKDeviceType`） | Adapter 产物 | Builder |
|---|---|---|
| `FIT_CLOUD` | `sdk-fitcloud-adapter` | `WKFitCloudKit.Builder` |
| `FLY_WEAR` | `sdk-flywear-adapter` | `WKFlyWearKit.Builder` |
| `SHEN_JU` | `sdk-shenju-adapter` | `WKShenJuKit.Builder` |
| `PROTO_TB` | `sdk-prototb-adapter` | `WKProtoTbKit.Builder` |
| `AB_MATE` | `sdk-abmate-adapter` | `WKAbMateKit.Builder` |

注册某个 adapter **不代表**该家族的所有设备都支持所有能力。功能支持取决于固件版本和各 ability 的 `Compat` API（见后续各功能指南）。

`WearKit-SDK-Android/README.md` 与 `CHANGED.md` 中记录的公开版本：**3.0.2.7**。所有 WearKit 产物必须保持**同一**版本。不要把 Maven 模块与版本不一致的本地 AAR 混用。

## 前置条件

- Android 应用模块、Kotlin、Java 8 语言级别。
- 宿主 App 的 `minSdk` **建议使用 26**。若不接入 AiKit 语音 AI（`com.topstep.aikit`），可降到 **24**。
- 蓝牙硬件与蓝牙权限（见[权限](#权限)一节）。
- 在创建任何 SDK 对象**之前**先初始化一个 Timber `Tree`。WearKit 通过 Timber 打日志，不会替你初始化。
- RxJava 3。不要把 `RxJavaPlugins.setErrorHandler` 换成吞掉所有异常的空实现。把 SDK 的忽略集合与你自己的 App 必须忽略的类型合并。

功能专用的宿主库（FFmpeg、AliAgent、`camera-core` 等）只在用到对应功能时添加——见下方 `dependencies` 注释。

### 常见重复类冲突

`sdk-fitcloud-adapter`（经 `sdk-fitcloud`）会带入必须依赖 `ext-realtek-bbpro` 与 `ext-realtek-file`（`wearKit.musicAbility` / `wearKit.eBookAbility` / `wearKit.albumAbility`）。宿主已有同类 Realtek 类并报 **duplicate class** 时，才在 adapter 上排除：

```kotlin
implementation("com.topstep.wearkit:sdk-fitcloud-adapter:$wearkitVersion") {
    exclude(group = "com.topstep.wearkit", module = "ext-realtek-bbpro")
    exclude(group = "com.topstep.wearkit", module = "ext-realtek-file")
}
```

本地 AAR 无 POM exclude：默认必须添加 `ext-realtek-bbpro-*.aar` 与 `ext-realtek-file-*.aar`。仅当宿主已有等价类并发生重复类冲突时才省略。

## 初始化顺序

在**主应用进程**的 `Application.onCreate` 中调用（sample 只在主进程创建 `RxBleClient` 和 `WKWearKit`）。

1. 初始化 Timber。
2. 用 **application** context 创建唯一的 `RxBleClient`：`RxBleClient.create(application)`。
3. 实现 `ProcessLifecycleManager`（或 `ProcessLifecycleObserver`）并注册，在进程进入前台/后台时调用 `setForeground(true/false)`。
4. 构造非空的 `List<WKWearKit.Builder>`。每个 builder 的参数为 `(Application, ProcessLifecycleObserver, RxBleClient)`。
5. 调用 `com.topstep.wearkit.core` 的 `val wearKit = buildWKWearKit(builders)`。空列表会抛 `IllegalArgumentException`。单个 builder 直接返回对应 kit；多个 builder 会包一层内部 manager，在连接后切换 active proxy。
6. 把 `wearKit.rxJavaPluginsIgnoreExceptions()` 合并进 `RxJavaPlugins.setErrorHandler`。
7. 在 application 作用域持有 `wearKit`（通常还有 `rxBleClient`）。不要每个 Activity 创建一个新的 kit。

部分家族有可选的 builder 开关（`setAutoSetTime`、`setAutoSetLanguage`、FitCloud AliAgent、FlyWear/ShenJu 的 `setLogPath`）。sample 使用构造器默认值。

`WKWearKit.release()` 存在，用于释放蓝牙辅助状态和各家族 kit。仅在需要拆除 kit 时调用；宿主通常不必调用。sample 让 kit 存活整个进程，没有调用 `release()`。

厂商测试开关（`PbSDK.COMPANY_ID_ALL`、连接方式）以及 `locationMapAbility.setLocation(...)` 放在 sample 的 `MyApplication` 里，在 `wearKitInit` **之后**。它们不属于最小初始化。只抄 `wearKitInit`；不需要 EPO / 设备 GPS、也不跑 sample 厂商测试时，不要抄这些。

## Kotlin 示例

基于 `WearKit-SDK-Android/sample/app/src/main/java/com/topstep/wearkit/sample/WearKitInit.kt` 与 `MyApplication.kt`。删掉你不发布的 adapter。Timber 需要自己初始化（sample 在 `AppLogger` 里初始化，因此 Timber 相关代码被注释掉了）。

```kotlin
package com.example.wear

import android.app.Activity
import android.app.Application
import android.os.Bundle
import android.util.Log
import com.polidea.rxandroidble3.RxBleClient
import com.topstep.wearkit.apis.WKWearKit
import com.topstep.wearkit.base.ProcessLifecycleManager
import com.topstep.wearkit.core.buildWKWearKit
import com.topstep.wearkit.fitcloud.WKFitCloudKit
import com.topstep.wearkit.flywear.WKFlyWearKit
import com.topstep.wearkit.prototb.WKProtoTbKit
import com.topstep.wearkit.shenju.WKShenJuKit
import io.reactivex.rxjava3.exceptions.CompositeException
import io.reactivex.rxjava3.exceptions.UndeliverableException
import io.reactivex.rxjava3.functions.Consumer
import io.reactivex.rxjava3.plugins.RxJavaPlugins
import timber.log.Timber

class App : Application() {

    lateinit var rxBleClient: RxBleClient
        private set
    lateinit var wearKit: WKWearKit
        private set

    override fun onCreate() {
        super.onCreate()
        if (BuildConfig.DEBUG) {
            Timber.plant(Timber.DebugTree())
        } else {
            Timber.plant(object : Timber.DebugTree() {
                override fun isLoggable(tag: String?, priority: Int): Boolean {
                    return priority > Log.DEBUG
                }
            })
        }
        rxBleClient = RxBleClient.create(this)
        wearKit = createWearKit()
    }

    private fun createWearKit(): WKWearKit {
        val processLifecycleObserver = AppProcessLifecycleManager().also {
            registerActivityLifecycleCallbacks(it)
        }
        val builders = ArrayList<WKWearKit.Builder>()
        builders.add(WKFitCloudKit.Builder(this, processLifecycleObserver, rxBleClient))
        builders.add(WKFlyWearKit.Builder(this, processLifecycleObserver, rxBleClient))
        builders.add(WKShenJuKit.Builder(this, processLifecycleObserver, rxBleClient))
        builders.add(WKProtoTbKit.Builder(this, processLifecycleObserver, rxBleClient))
        // builders.add(WKAbMateKit.Builder(this, processLifecycleObserver, rxBleClient))

        val wearKit = buildWKWearKit(builders)

        val ignoreExceptions = HashSet<Class<out Throwable>>()
        ignoreExceptions.addAll(wearKit.rxJavaPluginsIgnoreExceptions())
        RxJavaPlugins.setErrorHandler(RxJavaPluginsErrorHandler(ignoreExceptions))

        return wearKit
    }
}

private class AppProcessLifecycleManager : ProcessLifecycleManager(), Application.ActivityLifecycleCallbacks {
    private var startCount = 0

    override fun onActivityCreated(activity: Activity, savedInstanceState: Bundle?) = Unit

    override fun onActivityStarted(activity: Activity) {
        startCount++
    }

    override fun onActivityResumed(activity: Activity) {
        if (startCount == 1) {
            setForeground(true)
        }
    }

    override fun onActivityPaused(activity: Activity) = Unit

    override fun onActivityStopped(activity: Activity) {
        startCount--
        if (startCount == 0) {
            setForeground(false)
        }
    }

    override fun onActivitySaveInstanceState(activity: Activity, outState: Bundle) = Unit

    override fun onActivityDestroyed(activity: Activity) = Unit
}

private class RxJavaPluginsErrorHandler(
    private val ignores: Set<Class<out Throwable>>,
) : Consumer<Throwable> {

    override fun accept(t: Throwable) {
        if (handle(t)) return
        throw RuntimeException(t)
    }

    private fun handle(throwable: Throwable): Boolean {
        val cause = if (throwable is UndeliverableException) {
            throwable.cause
        } else {
            throwable
        } ?: return true

        if (cause is CompositeException) {
            var nullCount = 0
            for (e in cause.exceptions) {
                if (e == null) {
                    nullCount++
                } else if (isIgnore(e)) {
                    return true
                }
            }
            if (nullCount == cause.exceptions.size) {
                return true
            }
        } else if (isIgnore(cause)) {
            return true
        }
        return false
    }

    private fun isIgnore(throwable: Throwable): Boolean {
        val clazz = throwable::class.java
        for (ignore in ignores) {
            if (ignore.isAssignableFrom(clazz)) {
                return true
            }
        }
        return false
    }
}
```

`rxJavaPluginsIgnoreExceptions()` 是各家族集合的并集。例如 FitCloud 包含 `BleException`、`FcException`、`TimeoutException` 和 `InterruptedException`。未知类型的 undeliverable 错误仍然要抛出来；sample 的做法是重抛 `RuntimeException(t)`。

## 权限、生命周期、线程、错误与清理

### 权限

扫描/连接前先声明并申请蓝牙运行时权限。sample 的 `PermissionHelper` 遵循 `RxBleClient.getRecommendedScanRuntimePermissions`：

| API 级别 | sample 申请的蓝牙运行时权限 |
|---|---|
| 23 到 31 | `ACCESS_COARSE_LOCATION`、`ACCESS_FINE_LOCATION` |
| 31+ | `BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT` |

宿主 Manifest 中也要声明对应的 `<uses-permission>`。WearKit sample 已声明 `BLUETOOTH` / `BLUETOOTH_ADMIN`（maxSdk 30）以及 `BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT`。

WearKit sample Manifest 中的定位权限是给 EPO / 持续定位用的，与 Android 12 起扫描所需的蓝牙权限是两回事。相机、通讯录、短信、存储、Wi-Fi 权限都是功能专用的。

### 生命周期与线程

- `RxBleClient` 和 `WKWearKit` 建在 application 对象上，不要建在生命周期短的 Activity 里。
- 用 activity start/stop 驱动 `ProcessLifecycleManager.setForeground`（sample：第一个 activity resume 时置前台，最后一个 activity stop 时置后台）。
- SDK API 都是 RxJava 3。在后续指南里按 UI 或 IO 需要切换观察线程；初始化本身在 `Application.onCreate` 中同步执行。

### 错误与清理

- `buildWKWearKit` 至少需要一个 builder。
- kit 建好后再安装 `RxJavaPlugins.setErrorHandler`，这样才能拿到 `rxJavaPluginsIgnoreExceptions()`。
- 功能/扫描/连接的观察者随持有它的 lifecycle 释放（见扫描连接指南）。不要在每次 Activity `onDestroy` 时释放 application 作用域的 kit。
- 开启混淆时，SDK 模块自带 `consumer-rules.pro`（公共规则主要在 `sdk-base`）。如果宿主 AGP 老于 8.2，AAR 里的 sealed class 可能要求 **R8 8.2+**（SDK 仓库因此固定了 `com.android.tools:r8:8.2.47`）。当前 SDK AGP 为 8.6.0。

## 设备家族、固件、版本与功能限制

- 添加 adapter 依赖**并**注册对应 `Builder`，两者缺一不可。只加 Gradle 依赖、不注册 builder，该家族不可用。
- adapter 存在不代表固件与功能支持。
- 内部工程构建可能使用 `3.0.2.7-SNAPSHOT`；第三方 App 请使用 README 公开的版本（`3.0.2.7`），除非明确给了 snapshot 包。

## 验证步骤

1. 同步 Gradle：`sdk-core` 与所选 adapter 解析到 `3.0.2.7`（Maven），或对应 `*-v3.0.2.7.aar` 文件（本地）。
2. 启动 App 进程，`Application.onCreate` 无崩溃。
3. 确认 `wearKit` 已初始化，开关蓝牙时 `wearKit.isAdapterEnabled()` 能反映蓝牙状态（可选的冒烟检查；完整扫描见下一篇指南）。
4. Timber 已初始化的前提下可以看到 SDK 日志 tag（adapter 侧 FitCloud 用 `Fc#` 前缀，manager 用 `WK#`）。
5. 等扫描/连接接好后，再触发已知的 undeliverable BLE 错误路径；仅因为这些可忽略类型上报给 `RxJavaPlugins`，进程不得崩溃。

预期结果：得到一个进程级 `WKWearKit`，可用于 `scanner` / `connector`。此时还没有绑定任何手表。
