# 扫描、过滤、连接与断开

## 目的与适用范围

本指南覆盖用 BLE 扫描发现手表，再连接到进程级 `WKWearKit`（连接通道可能是 BLE 或经典蓝牙 SPP）：

- 用 `wearKit.scanner` 按单个 `WKDeviceType` 扫描。
- 使用 SDK 已为该家族应用的过滤（厂商 company ID、可选的空名称丢弃）。
- 用 `wearKit.connector.connect(...)` 连接，观察 `WKConnectorState`，再用 `close()` 或 `clear(...)` 离开。
- 可选的自动重连、配对与鉴权模式（`WKAuthMode`）。

功能 ability 须在 `WKConnectorState.CONNECTED` 之后再调用。

公开版本：**3.0.2.7**。

## 前置条件

- 已完成[准备工作：依赖与初始化](001.setup.md)。你已持有 application 作用域的 `WKWearKit` 与 `RxBleClient`。
- 为**每一个**要扫描的家族注册 `WKWearKit.Builder`。`wearKit.scanner.scan(type, …)` 会路由到该家族的 kit。只加 Gradle 依赖、不注册 builder，该 `WKDeviceType` 不可用。
- 蓝牙运行时权限与打开的蓝牙开关（见[权限](#权限生命周期线程错误与清理)一节）。
- 传给 `connect` 的稳定 `userId` 字符串。sample 用登录用户 id。除非产品约定允许，不要传空 id。
- 对应家族的实体设备正在广播。adapter 存在不保证某只手表一定会出现。

## 调用顺序

1. 确认蓝牙运行时权限与 `wearKit.isAdapterEnabled()`（或你自己的蓝牙开关观察）。API 30 及以下如果想和 Android BLE 协议栈行为一致，定位服务也要保持开启。
2. 订阅 `wearKit.scanner.scan(type, durationSeconds, checkLocationService, acceptEmptyName)`。
3. 收集 `WKScanResult`（`device`、`name`、`rssi`，可选 `projectNum` / `subProjectNum`）。用户选中设备后停止扫描（`dispose`）。
4. 如果 UI 需要展示连接中，先订阅 `wearKit.connector.observeConnectorState()` **再调** `connect`。用 `.startWithItem(wearKit.connector.getConnectorState())` 避免漏掉当前值。可选订阅 `observeConnectorError()`。
5. 调用推荐的 `connect` 重载（含鉴权 + 用户身体指标）。`connect` **不是** Rx 类型，调用后内部开始工作。
6. 只有 `WKConnectorState.CONNECTED` 才表示可以调 ability。`PRE_CONNECTED` 表示底层链路已建立（BLE GATT 或 SPP），但 SDK 还在跑准备流程。
7. 不想自动重连该地址：调 `close()` 离开。解绑（清除设备鉴权、可选清除 Android 配对、再 close）：订阅 `clear(removeBond)`。
8. 扫描与观察订阅随持有它的 lifecycle 释放。

正常交互不要调 `disconnect()` / `reconnect()`。两者都是 `@Discouraged`；KDoc 要求大多数 App 使用 `close()` 或 `clear()`。

## Kotlin 示例

基于 `DeviceScanActivity` / `ScannerHelper`（扫描）与 `DeviceActivity` / `SanagDeviceFeature`（连接）。时长单位是**秒**，与 `WKScanner` 和 `InternalBaseScanner` 一致（`take(..., TimeUnit.SECONDS)`）。WearKit sample 目前往 `durationSeconds` 传了 `120 * 1000`，那**不是**毫秒。除非你有意要超长扫描，请用 `120` 这类值。

`WKAuthMode` 是 `AuthMode` 的 `typealias`。sample 的 `DeviceActivity` 导入的是 `FwAuthMode`，即同一个枚举类型；第三方代码应导入 `WKAuthMode`。

```kotlin
package com.example.wear

import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity
import com.polidea.rxandroidble3.exceptions.BleScanException
import com.topstep.wearkit.apis.WKWearKit
import com.topstep.wearkit.apis.model.core.WKAuthMode
import com.topstep.wearkit.apis.model.core.WKConnectorState
import com.topstep.wearkit.apis.model.core.WKDeviceType
import com.topstep.wearkit.apis.model.core.WKScanResult
import io.reactivex.rxjava3.android.schedulers.AndroidSchedulers
import io.reactivex.rxjava3.disposables.CompositeDisposable
import io.reactivex.rxjava3.disposables.Disposable

class ScanConnectActivity : AppCompatActivity() {

    private val wearKit: WKWearKit get() = (application as App).wearKit
    private val disposables = CompositeDisposable()
    private var scanDisposable: Disposable? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        disposables.add(
            wearKit.connector.observeConnectorState()
                .startWithItem(wearKit.connector.getConnectorState())
                .observeOn(AndroidSchedulers.mainThread())
                .subscribe { state ->
                    when (state) {
                        WKConnectorState.DISCONNECTED -> { /* 空闲或已关闭 */ }
                        WKConnectorState.PRE_CONNECTING,
                        WKConnectorState.CONNECTING,
                        WKConnectorState.PRE_CONNECTED -> { /* 连接中 / 准备中 */ }
                        WKConnectorState.CONNECTED -> { /* 可以调 ability */ }
                    }
                }
        )
        disposables.add(
            wearKit.connector.observeConnectorError()
                .observeOn(AndroidSchedulers.mainThread())
                .subscribe { error ->
                    // error.throwable, error.retryNumber, error.retryContinue, error.bleScanException
                }
        )
    }

    fun startScan(type: WKDeviceType) {
        if (scanDisposable?.isDisposed == false) return
        if (!wearKit.isAdapterEnabled()) return

        scanDisposable = wearKit.scanner.scan(
            type = type,
            durationSeconds = 120,
            checkLocationService = true,
            acceptEmptyName = false,
        )
            .observeOn(AndroidSchedulers.mainThread())
            .subscribe(
                { result: WKScanResult -> onDeviceFound(result) },
                { throwable -> onScanError(throwable) },
                { /* 时长耗尽 */ },
            )
        disposables.add(scanDisposable!!)
    }

    fun stopScan() {
        scanDisposable?.dispose()
        scanDisposable = null
    }

    fun connect(type: WKDeviceType, address: String, userId: String) {
        stopScan()
        wearKit.connector.connect(
            type = type,
            address = address,
            authMode = WKAuthMode.AUTO,
            authCode = null,
            userId = userId,
            sex = true,
            age = 30,
            height = 175f,
            weight = 70f,
        )
    }

    fun disconnectAndForget() {
        wearKit.connector.close()
    }

    fun unbind(removeAndroidBond: Boolean) {
        disposables.add(
            wearKit.connector.clear(removeAndroidBond)
                .observeOn(AndroidSchedulers.mainThread())
                .subscribe({ /* 已解绑 */ }, { /* 打日志 */ })
        )
    }

    private fun onDeviceFound(result: WKScanResult) {
        // result.device.address, result.name, result.rssi
    }

    private fun onScanError(throwable: Throwable) {
        val reason = (throwable as? BleScanException)?.reason
            ?: BleScanException.UNKNOWN_ERROR_CODE
        when (reason) {
            BleScanException.BLUETOOTH_DISABLED,
            BleScanException.BLUETOOTH_NOT_AVAILABLE,
            BleScanException.LOCATION_PERMISSION_MISSING,
            BleScanException.LOCATION_SERVICES_DISABLED -> { /* UI 侧已拦截 */ }
            BleScanException.SCAN_FAILED_ALREADY_STARTED,
            BleScanException.UNDOCUMENTED_SCAN_THROTTLE -> { /* 稍后重试 */ }
            else -> { /* 未知；多次出现后提示用户开关蓝牙 */ }
        }
    }

    override fun onDestroy() {
        disposables.dispose()
        super.onDestroy()
    }
}
```

生产 App 通常把 `connect` / `close` 放在 application 作用域，避免页面跳转掉线。sample 的 `DeviceActivity` 在页面结束时调了 `close()`，那是 demo 的清理逻辑，不是 SDK 的强制约定。

## 扫描行为

`WKScanner.scan`：

| 参数 | 含义 |
|---|---|
| `type` | `WKDeviceType.FIT_CLOUD`、`FLY_WEAR`、`SHEN_JU`、`PROTO_TB` 或 `AB_MATE`。类型与当前家族 kit 对不上会抛 `IllegalArgumentException`。 |
| `durationSeconds` | 这么多**秒**后 Observable 结束（`sdk-base` 中的 `Observable.take(..., TimeUnit.SECONDS)`）。 |
| `checkLocationService` | 默认 `true`。为 true 且定位关闭时，RxAndroidBle / ShenJu 可能报 `BleScanException.LOCATION_SERVICES_DISABLED`。sample 把它设为 `false`，在 API 30 及以下自己展示定位横幅。 |
| `acceptEmptyName` | 默认 `false`。丢弃名称为 null 或空的广播。名称只有在连接运行时权限已授予时才能读到。 |

`WKScanner` KDoc：按家族过滤；前台 `SCAN_MODE_LOW_LATENCY` vs 后台 `SCAN_MODE_LOW_POWER`（来自 `ProcessLifecycleObserver.isForeground()`）；`BleScanException.UNDOCUMENTED_SCAN_THROTTLE` 重试一次（延迟上限 30 秒）。

每次发射的是 `WKScanResult`。判等包含 name、rssi 和 project 字段；`hashCode` 只用了 `device.hashCode()`。需要稳定列表时在 UI 按 address 去重。厂商 payload 足够长时填充 `projectNum` / `subProjectNum`（FitCloud / ProtoTb / AbMate 经 `BaseScanner` 路径）。adapter 里的 FlyWear 映射没有拷贝这两个字段。

不要一次 `WKScanner.scan` 调用扫所有家族，每次传一个 `WKDeviceType`。sample 的 `MainActivity` 为每个家族起了单独的 `DeviceScanActivity`。`type == null` 的 `ScannerHelper` 绕过 WearKit，直接用原生 `RxBleClient.scanBleDevices`，那是 demo 的“不过滤 BLE”路径，不是公开的 WearKit 过滤。

`WKScanner.qrcode(content)` 在接口上注明**尚未实现**。各 adapter 现状：ProtoTb 解析 URL（`ma`、`na`、`ty`，可选 `co`；`ty` 必须为 `w30`）得到 `WKQrCodeResult`；FitCloud、FlyWear、ShenJu adapter 返回 `null`。在接口注释更新前，不要把扫码绑定当作可移植的公开约定。sample 扫描页有扫码菜单和 Manifest activity 名称，但当前 sample 目录里没有 `DeviceQrCodeActivity` 源码。

## 连接、鉴权、重连与配对

推荐的重载（KDoc：“大多数 App 用这个”）：

`connect(type, address, authMode, authCode, userId, sex, age, height, weight)`

还有一个不带身体指标的重载。除非你会在 `CONNECTED` 后立刻调 `setUserInfo` / `syncUserInfo`，否则优先用第一个。

`WKAuthMode`：

| 取值 | KDoc |
|---|---|
| `BIND` | 该用户首次绑定这台设备。 |
| `LOGIN` | 重连 / 已绑定。 |
| `AUTO` | SDK 自选；sample 用这个。 |

`authCode`：只有从手表二维码拿到时才传。sample 传 `null`。

core manager 的 `connect` 会先切换 active 家族 proxy（`changeProxyKit`）再转发。连接后 `getDevice()` 持有 `BluetoothDevice` 直到 `close()`。`getDeviceType()` / `getDeviceToken()` 是 `@RestrictTo(LIBRARY_GROUP)`，宿主不得拿它们当连接判断。

`WKConnectorState`：

| 状态 | 含义 |
|---|---|
| `DISCONNECTED` | 空闲、`close()` 后、蓝牙关闭、自动重连关闭或被打断。需要原因时用 `getDisconnectedReason()` 取原因枚举。 |
| `PRE_CONNECTING` | 下一次尝试前的等待。 |
| `CONNECTING` | 正在连接（可能先扫描目标）。 |
| `PRE_CONNECTED` | 链路已通（BLE GATT 或 SPP），准备流程执行中；**不要**调功能 ability。 |
| `CONNECTED` | 就绪。BIND 时 `isBindOrLogin()` 为 true，LOGIN 时为 false。 |

core 连接器包装器的默认自动重连为 `WKAutoReconnectMode.BALANCED`，`setAutoReconnectInterval` **5** 秒。各模式：

| 模式 | 行为（来自 `AutoReconnectMode` KDoc） |
|---|---|
| `NEVER` | 不自动重连。 |
| `LOW_POWER` | 仅在 App 切前台、蓝牙打开或亮屏时触发，无定时器。 |
| `BALANCED` | 上述触发 + 定时器（前台约 5 秒；后台至少 5 秒，带退避）。 |
| `LOW_LATENCY` | 上述触发 + 前后台均为 5 秒定时器。 |

`close()` 断开并**清除**持有的设备（再次 `connect` 之前不会重连该地址）。`disconnect()` 保留设备，之后可能重连。`reconnect()` 在持有设备时重试。

`clear(removeBond)`：清除设备侧鉴权（部分固件会恢复出厂），`getDeviceCanBond()` 已配对时可选 `removeBond`，最后 `close()`。订阅返回的 `Completable`。

配对：manager 默认 `setAutoCreateBond(true)`。`createBond()` / `removeBond()` 返回 `Single<Optional<BluetoothDevice>>`。双模或可选配对硬件是家族相关的，不要默认认为需要经典配对。

连接后 `setUserInfo(...)` 总是覆盖设备侧用户指标。`syncUserInfo(WKUserInfo)` 在设备侧时间戳更新时可能保留设备数据；不支持的设备表现为强制写入。sample 界面见 `UserInfoActivity`。

## 权限、生命周期、线程、错误与清理

### 权限

蓝牙权限表同 [001.setup.md](001.setup.md#权限生命周期线程错误与清理)：API 23–30 用定位（`ACCESS_COARSE_LOCATION`、`ACCESS_FINE_LOCATION`）；API 31+ 用 `BLUETOOTH_SCAN` 与 `BLUETOOTH_CONNECT`。用 `RxBleClient.getRecommendedScanRuntimePermissions` / sample 的 `PermissionHelper`。

这些权限要在**宿主** Manifest 中声明。WearKit sample 已声明 `BLUETOOTH` / `BLUETOOTH_ADMIN`（maxSdk 30）以及 `BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT`。

API 31+ 按 RxAndroidBle 推荐权限集，扫描不再需要定位。31 以下需要定位权限，且通常还需要定位服务。sample 的 `DeviceScanActivity` 在 API 31+ 隐藏定位服务横幅。

`connect` **之前**先申请蓝牙权限（产品用到 EPO / 设备 GPS 时还要定位）。sample 的 `DeviceActivity` 先申请蓝牙权限再申请定位，最后 `connect`。

### 生命周期与线程

- `WKWearKit` 放 `Application`。连接器状态是进程级的。
- 扫描 UI 停止时释放 `scan()`（`ScannerHelper` 在 `onStop` 释放）。
- 扫描与连接器流在 `AndroidSchedulers.mainThread()` 上观察，用于更新 UI。
- 按 setup 的方式驱动 `ProcessLifecycleManager.setForeground`；它决定扫描功耗模式与重连触发。
- `connect` / `close` 可在主线程调用，它们是同步的 API 入口，内部启动异步工作。

### 错误与清理

- 扫描错误：`ScannerHelper.analysisScanError` 处理 `BleScanException` 的 reason。
- 连接错误：`observeConnectorError()` 发射 `WKConnectorError`（`throwable`、`retryNumber`、`retryContinue`，可选 `bleScanException`）。主 sample 没有订阅；Sanag demo 的注释里提到了它。
- `DISCONNECTED` 时 `getDisconnectedReason()` 是公开枚举（`INIT_STATE`、`ACTIVE_CLOSE`、`BT_DISABLED`、`DISCONNECT_TEMPORARY`、`DISCONNECT_DFU`、`AUTH_LOGIN_FAILED`、`AUTH_BIND_FAILED`、`AUTO_RECONNECT_DISABLED`、`ERROR_UNKNOWN`）。`getDisconnectedCause()` 仅 library-group 可用。
- 释放观察者；不要按 Activity 调 `release()`。
- 保留 setup 的 RxJavaPlugins 忽略集合，避免 undeliverable BLE 错误打崩进程。

## 设备家族、固件、版本与功能限制

- 各 adapter 内部按家族厂商 ID 过滤扫描（FitCloud、ProtoTb、AbMate、FlyWear、ShenJu）。未知手表会被过滤掉。`WKScanner` 不支持传自定义 company-ID 过滤。
- `SHEN_JU` 走 `SJUniWatch.startDiscovery` / `stopDiscovery`，不走公共 `BaseScanner` 路径。
- 未在广播、处于 DFU、已绑定其他手机的固件可能扫不到或报 `AUTH_*` 失败。
- `WKWearKit.observeAdapterEnabled(replay)` 可观察蓝牙开关；sample 扫描页用的是自己的 `flowBluetoothAdapterState`。
- 生产环境不要打开 `PbSDK.COMPANY_ID_ALL` 这类厂商测试开关（setup 也注明了）。

## 验证步骤

1. 初始化成功（[001.setup.md](001.setup.md#验证步骤)）。
2. 授予蓝牙权限；打开蓝牙（`checkLocationService` 为 true 且 API < 31 时还要开定位服务）。
3. 对附近正在广播的同家族手表开始扫描。在 `durationSeconds` 内应出现带合理名称和 RSSI 的 `WKScanResult`。`BaseScanner` 路径的 Timber 扫描日志包含 address / name / companyId。
4. 用 `WKAuthMode.AUTO` 执行 `connect`。UI 依次经过 `CONNECTING` / `PRE_CONNECTED` 到 `CONNECTED`。`getDevice()?.address` 与扫描到的 MAC 一致。
5. 关闭蓝牙：状态变为 `DISCONNECTED`（原因可能是 `BT_DISABLED`）。重新打开蓝牙：默认 `BALANCED` 下应自动开始重连，**前提是**你没有调过 `close()`，且不需要第二次 `connect`。
6. `close()`：设备被遗忘；再次 `connect` 之前定时器不会重连。
7. 状态非 `CONNECTED` 时，sample 的功能按钮 toast 提示“Device not connected”。

预期结果：`wearKit.connector` 持有一台设备，状态 `CONNECTED`，可以进入 ability 指南。
